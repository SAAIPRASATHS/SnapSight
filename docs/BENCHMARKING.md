## 1. Why We Benchmark

SnapSight's **core promise** is NPU-accelerated, battery-friendly AI on
Snapdragon. We benchmark to prove, with reproducible data, that:

1. NPU execution (QualcommAIHubProvider) beats CPU and GPU baselines on FPS
   and Joules-per-inference.
2. Concurrent multitask execution stays within Snapdragon's thermal and power
   envelope.
3. No commit regresses latency or throughput (future CI gate).

All numbers in `README.md` must be generated by the scripts in this guide.
Never hand-type values from ad-hoc runs.

## 2. Prerequisites

### 2.1 Hardware

For official results run on a **production Snapdragon HP PC**:

| Property | Required |
|---|---|
| Device | HP OmniBook Ultra / EliteBook / ProBook with Snapdragon X Elite or X Plus |
| RAM | ≥ 16 GB |
| Battery state | Start every run calibrated between 95 % and 100 % charge |
| AC power | Disconnect AC for battery-life / power-draw runs. Plug in for pure performance runs. |
| Cooling | Laptop on a flat hard desk, no case, room temp 22–24 °C |
| Other software | Close all apps except the benchmark shell. Disable OneDrive sync, Windows Defender real-time scanning during the run (remember to re-enable). |

### 2.2 Software

- Clean install of Windows 11 24H2 (or exact OS version under test).
- Latest Qualcomm Adreno + Hexagon NPU drivers from HP support (not Windows
  Update inbox drivers).
- SnapSight repo checked out at the exact commit SHA you will report.
- Python venv active with `backend/requirements.txt` installed.
- Provider of interest fully configured in both `.env` and
  `config/hardware.yaml` (validate with the `/config/runtime` endpoint first).

### 2.3 Calibration / Baseline Fixtures

Place these files in `tests/fixtures/` once per machine (they are GitIgnored
due to size):

| Fixture | Purpose | Where to get it |
|---|---|---|
| `sample_640x480.jpg` | Synthetic detection input (single frame) | Any 640×480 photograph containing obvious objects (person, car, dog, cup) |
| `sample_1080p_page.jpg` | OCR input | Photograph of a printed A4 page with ~400 words of body text at 12 pt |
| `sample_stt_10s.wav` | 16 kHz s16le mono, 10 s of spoken English | LibriSpeech test-clean subset, clip 1, or record your own reading of the Gettysburg Address |
| `sample_vlm_prompts.txt` | 10 prompts, one per line, of varying length | Curate yourself; include short ("What color is the mug?") and long ("Summarize the scene in three sentences.") examples. |

## 3. Benchmark Categories

| Name | What it measures | Frequency we run it |
|---|---|---|
| **Single-task, isolated** | Throughput + latency of one model running alone, warm, no I/O | Every PR touching providers or config |
| **Single-task, cold-start** | One-time cost of `ModelProvider.load()` | Once per release / weight refresh |
| **Multitask E2E** | All 4 models running concurrently on live camera + mic loops | Release candidate only, on real hardware |
| **Power / battery drain** | Watts drawn per task combo, projected runtime | Release candidate only |
| **Provider A/B** | Same weights, two providers (e.g. Hub vs. ONNX), same machine | When evaluating new backends or weight formats |

## 4. Metrics Collected

Every benchmark run MUST capture, at minimum, the fields below. Additional
fields are encouraged.

### 4.1 Inference Performance

| Metric | Unit | Definition |
|---|---|---|
| `fps` | frames / utterances / tokens per second | `completed_iterations / wall_time` |
| `latency_p50_ms` | milliseconds | Median end-to-end latency (task entry → result ready) |
| `latency_p95_ms` | milliseconds | 95th percentile latency |
| `latency_p99_ms` | milliseconds | 99th percentile latency |
| `first_token_ms` | milliseconds | (VLM / STT only) time from input complete to first output token |
| `tokens_per_second` | tokens / s | (VLM only) generation throughput after first token |

### 4.2 System Utilization (via `psutil` + vendor APIs)

| Metric | Unit | How |
|---|---|---|
| `cpu_util_pct` | % | `psutil.cpu_percent(interval=…)` averaged over the run |
| `cpu_freq_mhz` | MHz | `psutil.cpu_freq().current` — note we track Kryo perf-cluster peaks |
| `memory_working_set_mb` | MiB | `psutil.Process().memory_info().rss / (1024*1024)` |
| `gpu_util_pct` | % | Windows Performance Counter `\GPU Engine(*)\Utilization Percentage`, filtered to Adreno |
| `npu_util_pct` | % | `qai-hub runtime --utilization` (hexagon QNN runtime, sample every 500 ms) |
| `power_draw_watts` | W | Windows `Power Meter` counter or battery discharge slope × voltage, averaged |
| `joules_per_1000_inferences` | J | `power_draw_watts × (1000 / fps)` — energy efficiency figure of merit |

### 4.3 Environment Metadata (Always Attach)

- `commit_sha` — output of `git rev-parse HEAD`
- `os_version`, `os_build` — `systeminfo | findstr /B /C:"OS"`
- `driver_versions` — Adreno + Hexagon driver packages from Device Manager
- `hardware.yaml` contents (inline or base64)
- `.env` contents (redact secrets)
- Raw JSON trace file location

## 5. Running the Benchmark Script

SnapSight ships a unified benchmark entry point under
`backend/benchmarks/run_benchmarks.py`. It:

1. Parses CLI args.
2. Instantiates the configured provider (bypasses FastAPI for minimum
   overhead, or routes through FastAPI to measure E2E).
3. Runs the warmup phase.
4. Runs N iterations or a fixed-duration window.
5. Collects all §4 metrics via hooks.
6. Writes structured JSON and a human-readable markdown report to disk.

### 5.1 Command Line Reference

```bash
cd backend

python benchmarks/run_benchmarks.py --help
# Usage:
#   run_benchmarks.py [OPTIONS]
#
# Options:
#   --mode [isolated|multitask|ab|cold_start]
#   --tasks [object_detection,speech_to_text,ocr,vision_language]
#   --backend [AUTO|QUALCOMM_AI_HUB|ONNX|PYTORCH|MOCK]
#   --iterations INTEGER          Number of inferences per task (isolated mode)
#   --duration INTEGER            Wall-clock seconds per task (preferred)
#   --route-through-fastapi       Send requests over HTTP/WebSocket instead of direct provider call
#   --output PATH                 Output directory (default: ./benchmark_results/)
#   --tag TEXT                    Short label to tag this run (e.g. "xelite-pre")
#   --help
```

### 5.2 Example: Single-Task, Isolated — Object Detection (NPU)

```bash
cd backend

python benchmarks/run_benchmarks.py \
  --mode isolated \
  --tasks object_detection \
  --backend AUTO \
  --duration 60 \
  --route-through-fastapi \
  --output ../benchmark_results \
  --tag "xelite_yolov8n_npu"
```

Output structure:

```
benchmark_results/
├── xelite_yolov8n_npu_20260930T121500.json        # Full structured metrics
├── xelite_yolov8n_npu_20260930T121500.md          # Human-readable report
└── traces/
    └── xelite_yolov8n_npu_latency_trace.csv       # per-iteration latencies
```

### 5.3 Example: All Four Tasks, Isolated

```bash
python benchmarks/run_benchmarks.py \
  --mode isolated \
  --tasks object_detection,speech_to_text,ocr,vision_language \
  --backend AUTO \
  --duration 30 \
  --output ../benchmark_results \
  --tag "xelite_all_tasks_npu"
```

## 6. Running Manual Isolated Benchmarks

If the benchmark harness is not yet implemented and you need results now, use
the scriptable one-liners below. They approximate the harness with native
tools.

### 6.1 Detection Latency / FPS (direct provider)

```python
# save as tmp_bench.py, run:  python tmp_bench.py
import time, statistics, numpy as np
from backend.providers import ModelProviderFactory
from backend.config import load_hw_config

cfg = load_hw_config("../config/hardware.yaml")
p = ModelProviderFactory.resolve("AUTO", "CPU", cfg)
p.load(cfg)

# Warm-up
frame = np.random.randint(0, 255, (480, 640, 3), dtype=np.uint8)
for _ in range(20):
    p.detect(frame)

# Measurement (N iterations)
N = 500
lats = []
t0 = time.perf_counter()
for _ in range(N):
    s = time.perf_counter()
    result = p.detect(frame)
    lats.append((time.perf_counter() - s) * 1000)
elapsed = time.perf_counter() - t0

print(f"fps          = {N / elapsed:.2f}")
print(f"lat_p50_ms   = {statistics.median(lats):.2f}")
lats_sorted = sorted(lats)
print(f"lat_p95_ms   = {lats_sorted[int(0.95*N)]:.2f}")
print(f"lat_p99_ms   = {lats_sorted[int(0.99*N)]:.2f}")
```

### 6.2 CPU + Memory (sampling in parallel)

In a second terminal, while the benchmark runs:

```bash
# Windows:  typeperf
typeperf "\Process(uvicorn)\% Processor Time" "\Process(uvicorn)\Working Set - Private" \
  -si 1 -sc 70 -o perf_raw.csv
# Post-process in Excel: average % Processor Time / logical_cpus
```

### 6.3 NPU Utilization (Qualcomm AI Hub)

```bash
# In a third terminal:
qai-hub runtime utilization --sample-interval-ms 500 --duration 60 --csv npu_util.csv
# Report the mean of the `hexagon_npu_total_pct` column.
```

Merge the three CSVs into a single JSON file by hand or with a helper script
and attach to the result folder.

## 7. Multitask End-to-End (E2E) Benchmark

This is the closest simulation of real-world copilot usage:

```bash
cd backend

python benchmarks/run_benchmarks.py \
  --mode multitask \
  --tasks object_detection,speech_to_text,ocr,vision_language \
  --backend AUTO \
  --duration 300 \
  --route-through-fastapi \
  --output ../benchmark_results \
  --tag "xelite_multitask_5min"
```

The multitask harness:

1. Starts the FastAPI app in a subprocess (real uvicorn, matching production).
2. Opens a WebSocket to `/ws/camera` and pushes frames at 30 FPS.
3. Opens a WebSocket to `/ws/stt` and pushes 16 kHz PCM chunks from the STT
   fixture in a loop.
4. Triggers OCR once per second via POST.
5. Submits a VLM prompt every 15 s via `/ws/vlm`.
6. Records per-channel results plus process-wide CPU/memory/NPU/power.
7. After 5 minutes reports summary stats plus any dropped frame counts.

### Battery Discharge Measurement (Release Candidate Only)

1. Unplug AC.
2. Start the multitask benchmark in `--duration 3600` (1 hour).
3. Before + after, record:
   ```powershell
   (Get-WmiObject -Class Win32_Battery).EstimatedChargeRemaining
   ```
4. Projected runtime:
   ```
   projected_hours = 1.0 / ((start_pct - end_pct) / 100)
   ```

## 8. Comparing Provider Backends (A/B Runs)

To produce the "Qualcomm AI Hub vs. Generic Baseline" table in the README:

```bash
TAG_BASE="baseline_xelite"
for BACKEND in QUALCOMM_AI_HUB ONNX PYTORCH; do
    python backend/benchmarks/run_benchmarks.py \
      --mode isolated \
      --tasks object_detection \
      --backend $BACKEND \
      --duration 60 \
      --output benchmark_results \
      --tag "${TAG_BASE}_${BACKEND,,}"
done
```

Three JSON files are written. Combine them into one diff-friendly comparison
table using:

```bash
python backend/benchmarks/compare.py \
  benchmark_results/*_objectdetection_*.json \
  --md > ab_summary.md
```

The Joules-per-1000-inferences row is the headline number for sales / PM
discussions — **this is where Snapdragon's NPU advantage is most visible**.

and replace each `_TBD_` placeholder with the matching value from
`/tmp/evidence_snippet.md`.

place so future benchmark runs can fill the gap.

Every time you update the README tables, also:

1. Commit the new JSON + CSV + `.md` reports to a separate
   `benchmark-artifacts` branch (or attach them to the GitHub release).

   - Date
   - Device
   - Commit SHA
   - Link to artifact ZIP
   - Runner name / initials

## 10. Troubleshooting Benchmarks

### 10.1 Latency numbers are 2× higher than expected

- **Forgot warmup phase.** The first ~10 inferences include JIT / QNN context
  compile. The official harness always does 20 warmup iterations before
  timing; manual runs must do the same.
- **Confidence threshold = 0 causing too many boxes.** NMS cost scales with
  proposal count. Re-run with `CONFIDENCE_THRESHOLD=0.25`.

### 10.2 NPU shows 0 % utilization during detection run

- Confirm the provider is really `QualcommAIHubProvider` via `/config/runtime`.
- Check `qai-hub test <model_folder>` reports `Runtime: Hexagon NPU`. If it
  says "CPU fallback", the weight package is missing QNN binaries — re-download
  the `-quant` (INT8) variant from the Hub.
- The NPU utilization sampling period might be too long to catch the tiny
  inference windows. Lower to `--sample-interval-ms 100`.

### 10.3 "Out of memory" halfway through multitask runs

- UMA Snapdragon systems share memory across CPU/NPU/GPU. Reduce
  `INFERENCE_FPS` for detection so fewer frames are buffered in flight.
- Disable VLM if it uses a large decoder (the 1.4B MobileVLM fits; a 7B Llama
  does not in 16 GB).

### 10.4 Power draw readings look too low / high

- Windows power-meter counters report **package power** for modern SOCs, which
  is what we want; but some BIOS revisions under-report. Always cross-check
  against battery discharge slope (the gold standard for laptops).
- Unplug all USB accessories; a dock + external monitor can add 5–15 W.
- Screen brightness: lock to 200 nits or 50 % via the OSD between runs.

### 10.5 Benchmark results are not reproducible run-to-run

- Always disable Windows Update active hours, location tracking, and
  "Tips and suggestions" before a release-run.
- Use `powercfg /setactive 8c5e7fda-e8bf-4a96-9a85-a6e23a8c635c` (High
  Performance) before the run, then revert to Balanced after.
- Stop Windows Search indexer:
  ```powershell
  Stop-Service WSearch
  ```
